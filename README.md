# Memo · TT版 1.0.28

安装地址：https://github.com/cszgezi-lab/Memo-TT

面向 TauriTavern 2.2。安装并打开 Memo，在设置中填写总结、动态人设、向量和重排连接；新安装的自动总结与自动人设默认关闭，按需要在总览开启。原版拾忆仍从原地址使用，新旧版本的配置、Key、存档和注入标识独立；同一聊天请只启用其中一个版本。

设置“标签管理”复用提取/排除规则，用于总结与人设读取选中的聊天正文，支持 XML 块和正则预览，不修改聊天原文。普通召回中的原文依据不会重新套用当前过滤规则。日志页集中导出日志、纯配置和当前聊天备份；API Key 不进入导出。头像保存在本设备界面存储，不进入模型请求和聊天备份。

总结、人物、字典、向量、重排和最终注入使用原版生产引擎；世界信息、知识库和助手独立功能不再提供。动态人设仍可只读核对角色卡和已绑定世界书，并在当前请求中替换对应人物，不改原书正文。

本地协议模型与隔离宿主用于验证接口联动；真实模型语义与 Android 实机效果需分别验收。浏览器只提示派发下载时，请确认文件实际保存。

主总结、修复复核及动态人设采用流式传输，收到完整回复并通过原有校验后才保存；中断和错误不会作为成功结果落地。已知渠道错误会尽早结束等待，恢复仍受现有次数上限、限流与冷却约束。主总结预设新增“破甲区”：反截断开关和可编辑破甲词；头部及用户输入长填充可选，默认关闭；旧版遗留的开启值不会自动生效，需在破甲区重新开启并保存。两项全开约增加2.2万字符/次。破甲词计入预算，工具参数与记忆完整性仍严格校验；这些选项不能保证解决服务商截断或限流。兼容工具及填充文本的 MIT 署名见 LICENSE.txt。

1.0.16：完整总结 JSON 可在渠道漏发结束标记时继续校验保存；真实截断、长度限制和内容拦截分别处理。同步清理未执行的不足整批空尾项，事件合并本地收尾，无法合并的有效记录独立保留，不增加模型请求。

1.0.17：传输失败时在日志保留最多8192字符的响应首尾原文、实际长度和结束状态，已遮蔽已知Key和凭据字段；日志及完整排障包均可导出。只截取既有响应，不增加请求，成功回复不记录原文。

1.0.19：识别渠道放在流式正文中的明确内容拒绝，保留响应证据，不再误报传输中断。恢复可选头部/用户输入长填充，与动态人设共用；默认关闭，不增加请求次数或自动重试，不改变旧记忆。

1.0.19：日志补充完整传输后解析失败的回复，最多8192字符并遮蔽已知密钥；导出日志可附带当前聊天仍在缓存中的失败回复，无需重跑批次。修正TT原生内容拒绝分类，解析失败后省去无用的全聊天刷新。该更新不增加请求或重试次数。

1.0.20 提示词对照版：恢复1.0.13精简前的内置总结说明，保留1.0.19其余运行行为；自定义预设和破甲配置保持。只做本地中性数据验证，未证明渠道拒绝已解决。此次没有加入格式兼容或缺楼处理的新行为。

1.0.27：新增“仅总结本批正文”开关，默认关闭；开启后不向总结模型发送旧记忆、范围外衔接正文及外部状态。同步与自动从最后已处理批次之后继续；失败时本次停住，下次触发从后续楼层继续。跳过计入进度，失败记录保留可手动重试，不生成虚假摘要。

1.0.28：删除主总结批次后按有效批次重算进度，全部删除可从原起点重来；失败跳过仍从后面继续。主总结列表只显示真实批次，同步逐批创建、逐批执行。强制停止持久关闭自动总结，明确开启或手动同步才再执行；首页改为“开启自动／暂停自动”和“自动设置”。正文范围设置保持，可保存后用于新建或重新生成的批次。
